Calibration records
===================

A ``CalibrationRecord`` (module :mod:`PharmaPy.Records`) stores one
parameter-estimation case as versioned JSON: the observations as
``Experiment`` and ``Measurement`` objects (see :doc:`experiment_measurement`),
where the data came from and how they may be shared, how they were
transformed, the parameters with their units, bounds and fitted values, the
model revision, the optimizer settings and outcome, the parameter covariance
and stored model fields. A record is reloaded and rerun to check that the
fit is reproduced.

Records are an exchange format, not a second observation hierarchy: the
in-memory objects remain ``Experiment`` and ``Measurement``, which a record
serializes and reconstructs exactly. No unit conversion is performed: unit
and basis labels document the stored numbers, which must already be in the
units and physical basis of the model.

Record schema
-------------

A record file is one JSON object. Its entries, in the order
``CalibrationRecord.save`` writes them, are listed below. Ordered collections
are JSON arrays in declared order and are never sorted, so experiment,
measurement, parameter and field order survive a round trip. Floats are
written with Python's shortest round-trip representation and read back bit
for bit. JSON has no ``NaN``: a missing value is written as ``null`` and read
back as ``NaN``. Infinite values are rejected.

``schema`` and ``schema_version``
   ``'pharmapy.calibration-record'`` and the format version, currently ``1``.
   Other values are rejected when reading.
``case`` and ``description``
   Identifier of the calibration case and optional free text.
``model``
   The calibrated model: ``name`` (model or callback identifier, e.g.
   ``'BatchReactor.paramest_wrapper'``), ``revision`` (a user-supplied
   revision of the model code such as a git commit; never detected),
   ``pharmapy_version`` (detected from the installed ``pharmapy-sim``
   distribution when it provides the imported package, otherwise ``null``)
   and ``description`` (equations and assumptions).
``sources``
   At least one data source, each with ``name``, ``origin``, ``sharing``
   (license or sharing conditions) and the optional ``description``,
   ``citation``, ``uri``, ``revision``, ``sha256`` (64 lowercase hexadecimal
   digits of ``hashlib.sha256(data).hexdigest()`` of the original file) and
   ``role`` (e.g. ``'calibration'``). ``origin`` is one of

   * ``'experimental'``: measured data;
   * ``'literature'``: data taken from a publication;
   * ``'synthetic'``: data generated by a model, for example a verification
     fixture; they are not evidence of an empirical calibration;
   * ``'simulation'``: outputs of a simulation study;
   * ``'unknown'``: the provider of the data did not record their origin.
     Never choose a plausible origin instead. Such a source must state what
     is known (where the data were obtained, under which conditions they
     are shared, which issue tracks the missing information) in ``sharing``
     and in ``description``, which is required for this origin
     (``ValueError`` otherwise).
``transformations``
   Steps applied to the source data before fitting, in application order:
   ``description`` (what was done, including the units of any constant),
   ``fields`` (measurement or stored-field names; empty means all data),
   ``source`` (name of a source) and ``parameters`` (constants used, e.g.
   ``{"factor": {"value": 0.4, "units": "mol/L"}}``). They document how the
   stored observations were derived and are not re-applied by PharmaPy.
``output_names``
   The ``output_names`` of ``ParameterEstimation``: names of the model
   callback output columns, needed when measurements select their field by
   name; ``null`` otherwise.
``parameters``
   The parameter vector in model-callback order. Each parameter has
   ``name``, ``units`` (``'-'`` when dimensionless), ``seed`` (initial value
   of an optimized parameter or value of a fixed one), ``lower`` and
   ``upper`` (bounds in ``units``, ``null`` for an unbounded side; passed to
   IPOPT and ignored by Levenberg-Marquardt), ``optimized``, ``fitted``
   (``null`` before fitting and for fixed parameters) and ``description``.
``experiments``
   The experiments in fitting order. Each has ``name``, ``args`` and
   ``kwargs`` (the callback association, ``func(params, x, *args,
   **kwargs)``, in the units the model defines) and ``measurements`` in
   declared order. A measurement has ``name``, ``field`` (an ``int``
   output column or a ``str`` output name), ``units``, ``basis`` (optional
   label such as ``'molar concentration'``), ``x_units`` (``'s'`` for time
   in seconds), ``x`` and ``values`` (shape ``(n,)``, ``null`` marking a
   missing observation) and ``uncertainty``: the standard deviation of the
   measurement error, one entry per sample in the units of ``values``, or
   ``null`` when none is declared. Every measurement must declare ``units``
   and ``x_units``. Callback values that JSON cannot represent exactly
   (tuples, NumPy scalars and arrays) are objects tagged by the reserved key
   ``"__type__"`` (``"tuple"``, ``"numpy_scalar"`` or ``"ndarray"``) that keep
   their dtype, byte order included.
``weight_matrix``
   ``null``, or the measurement-error covariance of the measurement
   columns at one sample: ``index`` and ``columns`` hold the measurement
   names in column order and ``values`` the matrix, entry ``(i, j)`` in the
   product of the units of measurements ``i`` and ``j``.
   It is stored as the effective symmetric, positive-definite matrix and is
   not allowed when the measurements declare uncertainties.
``solver``
   ``null`` before fitting, otherwise the optimizer settings: ``method``
   (``'LM'`` or ``'IPOPT'``), ``options`` (the ``optim_options`` passed to
   ``optimize_fn`` without the entries it writes itself), ``model_solver``
   (settings of the model's own integrator, for documentation),
   ``outcome`` (e.g. ``stop_criterion``, ``num_iter``, ``num_fun_eval`` and
   ``objective``, ``1/2 * r @ r`` of the weighted residuals) and
   ``derivatives``: ``jacobian`` is ``'model_sensitivities'``, ``'jac_fun'``
   or ``'finite_difference'`` and ``dx_finitediff`` is ``'default'`` (the
   relative step ``ParameterEstimation`` installs), ``'callable'`` (a user
   function, which a record cannot hold and must be passed again on a
   rerun) or the numeric step in parameter units, which is replayed.
``covariance``
   ``null``, or the parameter covariance of the optimized parameters:
   ``parameters`` (their names, in record order), ``include_mse`` and
   ``values`` (shape ``(k, k)``). ``include_mse`` states the form:
   ``true`` for ``get_covariance(include_mse=True)``, which
   ``optimize_fn`` returns (scaled by the residual mean square, like
   ``curve_fit(..., absolute_sigma=False)``), ``false`` for the unscaled
   ``inv(J @ J.T)``. Entry ``(i, j)`` has the product of the units of
   parameters ``i`` and ``j`` when the weighted residuals are dimensionless
   (declared uncertainties, or a ``weight_matrix`` of error covariances in
   squared measurement units), for both forms. With the default identity
   weighting this holds for the ``include_mse=True`` form only if every
   residual has the same physical unit, as in the Ziegler case below (all
   [mol/L]); the unscaled form is then additionally divided by that unit
   squared. With identity weighting of residuals in different units (e.g.
   [mol/L] and [K]) neither form is a physical covariance (see
   ``ParameterEstimation.get_covariance`` and
   :doc:`experiment_measurement`).
``fields``
   Stored model fields. Each has an ``identity`` (``name``, ``kind``,
   ``units``, ``basis``, ``description``), ``experiment`` (an experiment
   name or ``null``), ``x_units``, ``x`` (shape ``(n,)``), ``values`` of
   shape ``(n,)``, or ``(n, m)`` for ``m`` labelled components with their
   labels in ``columns`` (``null`` for one-dimensional values), ``null``
   marking a missing value. ``kind`` is ``'state'`` (differential state),
   ``'algebraic'`` (algebraic variable), ``'quality_attribute'`` (product
   quality attribute) or ``'measurement_prediction'`` (the model output of
   a measurement on its experiment's model grid). The triple (experiment,
   kind, name) identifies a field, so a state and a measurement prediction
   may share a name. A measurement prediction must name its experiment and
   a measurement name of the record, declared by any experiment, with that
   measurement's units and basis and its experiment's ``x_units``.

Templates
---------

PharmaPy ships a record template, ``calibration_record``, an unfitted
record that shows the sections by example; the fit results ``solver``,
``covariance`` and ``weight_matrix`` are ``null``. ``template_text()``
returns its JSON text and ``load_template()`` the record:

.. testcode::

   from PharmaPy.Records import load_template

   template = load_template()
   print(template)
   print(template.solver, template.fitted_values)
   measurement = template.experiments['TEMPLATE-run'].measurements['T']
   print(measurement.values.tolist(), measurement.uncertainty.tolist())

.. testoutput::

   CalibrationRecord(case='TEMPLATE-case', experiments=['TEMPLATE-run'], parameters=['k'])
   None None
   [325.6, nan] [0.5, 0.5]

The template is an unfitted record: ``solver``, ``covariance``,
``weight_matrix`` and the ``fitted`` values are ``null``. Text entries starting with ``TEMPLATE`` are
placeholders. Its numbers are the synthetic decay example of
:doc:`experiment_measurement` (the ``hot`` run), not data; its source
therefore has origin ``'synthetic'`` and its sharing text says it is an
illustrative template. It holds:

* one experiment, ``TEMPLATE-run``, with callback ``args`` (the initial
  concentration [mol/L]) and ``kwargs`` (the temperature rise [K*L/mol] and
  initial temperature [K]), and two measurements: ``c_A`` [mol/L] with one
  uncertainty per sample, and ``T`` [K] whose sample at 4 s is ``null`` to
  show a missing observation;
* one data source and one transformation that uses the values as stored
  (a factor of 1.0 [-]);
* one parameter, the rate constant ``k`` [1/s], with a lower bound of 0 and
  no upper bound;
* a model revision and a stored ``'state'`` field, the decay model's
  ``c_A = c_A0 * exp(-k t)`` at the seed ``k``.

To describe a new case, write ``template_text()`` to a file, replace the
placeholders and numbers, and read it with ``CalibrationRecord.load``, which
validates every entry. JSON has no comments; the sections are described in
`Record schema`_ above.

To fit a filled-in record ``filled``, build the estimator from it, fit, and
capture the fit with the record's provenance:

.. code-block:: python

   inputs = filled.estimation_inputs()
   estimator = ParameterEstimation(func, **inputs)  # func: the model callback
   estimator.optimize_fn(verbose=False)
   fitted = CalibrationRecord.from_estimation(
       estimator, inputs['x_data'], case=filled.case,
       parameter_units=[item.units for item in filled.parameters],
       model=filled.model, sources=filled.sources,
       transformations=filled.transformations, fields=filled.fields,
       description=filled.description,
       bounds=[(item.lower, item.upper) for item in filled.parameters
               if item.optimized])

``from_estimation`` takes the parameter names, seeds and optimize flags from
the estimator and the bounds from ``bounds``; it does not carry the
parameters' ``description`` entries.

Reloading and rerunning a fit
-----------------------------

The documented path captures a fitted estimator, saves the record, reloads
it, rebuilds the estimator with ``estimation_inputs()``, refits it with
``optimizer_inputs()`` and checks the result with ``check_rerun``. The model
callback, here the closed-form decay of :doc:`experiment_measurement`, is
identified by the record's ``model`` entry but is code: the user supplies it
again.

.. testcode::

   import json
   import os
   import tempfile

   import numpy as np
   from PharmaPy.ParamEstim import Experiment, Measurement, ParameterEstimation
   from PharmaPy.Records import CalibrationRecord, DataSource, ModelRevision


   def decay(params, time_s, initial_mol_l, rise_k_l_mol=0.0, temp0_k=300.0):
       """Return c_A [mol/L] and T [K] of a first-order A -> B reaction.

       Parameters
       ----------
       params : numpy.ndarray
           Rate constant k, shape (1,) [1/s].
       time_s : numpy.ndarray
           Model grid, shape (n_times,) [s].
       initial_mol_l : float
           Initial concentration of A [mol/L].
       rise_k_l_mol : float, optional
           Adiabatic temperature rise per converted concentration [K*L/mol].
       temp0_k : float, optional
           Initial temperature [K].

       Returns
       -------
       numpy.ndarray
           Shape (n_times, 2); column 0 is c_A [mol/L], column 1 is T [K].
       """
       converted = initial_mol_l * (1 - np.exp(-params[0] * time_s))  # [mol/L]
       return np.column_stack((initial_mol_l - converted,
                               temp0_k + rise_k_l_mol * converted))


   experiments = {
       'hot': Experiment(
           {'c_A': Measurement(0, [0.0, 1.0, 2.0, 4.0],  # [s]
                               [2.010, 1.200, 0.750, 0.265],  # [mol/L]
                               uncertainty=0.02, units='mol/L'),
            'T': Measurement(1, 2.0, 325.6, uncertainty=0.5, units='K')},
           args=(2.0,), kwargs={'rise_k_l_mol': 20.0}),
       'cold': Experiment(
           {'c_A': Measurement(0, [0.5, 1.5, 3.0],  # [s]
                               [0.785, np.nan, 0.220],  # [mol/L]
                               uncertainty=[0.01, 0.01, 0.02], units='mol/L')},
           args=(1.0,), kwargs={'rise_k_l_mol': 10.0, 'temp0_k': 290.0})}

   estimator = ParameterEstimation(decay, [0.3], experiments,
                                   name_params=['k'])  # seed k [1/s]
   estimator.optimize_fn(verbose=False)
   record = CalibrationRecord.from_estimation(
       estimator, experiments, case='decay-guide', parameter_units=['1/s'],
       model=ModelRevision(
           'decay', revision='calibration_records.rst decay model, v1',
           description='first-order A -> B with an adiabatic temperature '
                       'rise, closed form'),
       sources=[DataSource(
           'guide', 'synthetic',
           'synthetic values written for this guide; no external data',
           description='synthetic data of the Experiment/Measurement '
                       'guide')])
   print(record)
   print(f"k = {record.fitted_values[0]:.4f} 1/s")
   print([(field.experiment, field.identity.kind, field.name)
          for field in record.fields])

   with tempfile.TemporaryDirectory() as directory:
       path = os.path.join(directory, 'decay-guide.json')
       record.save(path)
       with open(path, encoding='utf-8') as file:
           saved = json.load(file)
       loaded = CalibrationRecord.load(path)
   print(saved['experiments'][1]['measurements'][0]['values'])
   print(loaded == record, loaded.model.revision)

.. testoutput::

   CalibrationRecord(case='decay-guide', experiments=['hot', 'cold'], parameters=['k'])
   k = 0.5011 1/s
   [('hot', 'measurement_prediction', 'c_A'), ('hot', 'measurement_prediction', 'T'), ('cold', 'measurement_prediction', 'c_A'), ('cold', 'measurement_prediction', 'T')]
   [0.785, None, 0.22]
   True calibration_records.rst decay model, v1

The capture adds one ``'measurement_prediction'`` field per experiment for
every measurement name of the estimation: the model output on the
experiment's model grid at the fitted parameters. The ``cold`` run therefore
gets a ``T`` prediction although it does not measure ``T``. The missing cold
observation is ``null`` in the file and ``NaN`` again after loading; the
reloaded record equals the captured one. The model ``revision`` is
user-supplied, here an identifier of the guide's own model definition;
PharmaPy never detects it, so pass the commit or version of your model
code.

The rerun replays bit-identical data, seeds and options through the same
deterministic Levenberg-Marquardt iterations, so the tolerance passed to
``check_rerun`` can be a few units in the last place. Choose it for the
model and solver at hand and state why it is adequate; across platforms or
library versions a looser tolerance may be needed.

.. testcode::

   rebuilt = ParameterEstimation(decay, **loaded.estimation_inputs())
   rebuilt.optimize_fn(verbose=False, **loaded.optimizer_inputs())
   replay_rtol = 4 * np.finfo(float).eps  # [-], four units in the last place
   difference = loaded.check_rerun(rebuilt, rtol=replay_rtol,
                                   atol=0.0)  # atol [1/s]
   print(f"k = {rebuilt.params_convg[0]:.4f} 1/s, "
         f"|difference| <= {replay_rtol:.1e} * k: "
         f"{bool(difference[0] <= replay_rtol * loaded.fitted_values[0])}")

   rerun = loaded.rerun(decay, rtol=replay_rtol, atol=0.0)  # the same steps
   print(f"k = {rerun.params_convg[0]:.4f} 1/s")

.. testoutput::

   k = 0.5011 1/s, |difference| <= 8.9e-16 * k: True
   k = 0.5011 1/s

``check_rerun`` raises ``RerunMismatchError`` naming each parameter that
differs beyond ``atol + rtol * |recorded|``, and ``ValueError`` if the
estimator was not built from the record (experiment order, parameter names
or optimize flags differ). ``rerun(func, rtol=..., atol=...)`` performs the
rebuild, refit and check in one call. A fit that used a ``jac_fun`` or a
callable ``dx_finitediff`` needs them again:
``rerun(func, ..., jac_fun=...)``.

Fits through SimulationExec
~~~~~~~~~~~~~~~~~~~~~~~~~~~

``from_estimation`` also accepts the estimator that
``SimulationExec.SetParamEstimation`` builds from ``Experiment`` objects.
The record then stores the wrapper keywords each experiment was evaluated
with (``modify_phase``, ``modify_controls`` and ``run_args``), so it reruns
both through ``SetParamEstimation(**record.estimation_inputs())`` without
modifier arguments and directly with
``record.rerun(unit.paramest_wrapper, ...)``. Building the flowsheet unit
is the user's code. The sketch below mirrors
``tests/test_records_ziegler_case.py``, which runs it for the Ziegler
batch-reactor case of :doc:`param_estimation_solved` (it needs the optional
Assimulo solver). Its helper functions and constants are those of that test;
the comments state what they hold.

.. code-block:: python

   # Test constants: PURE (path of pure_components_ziegler.json), REACTIONS
   # (['A --> B', 'A --> C', 'B --> C', 'B --> D']), NUM_REACTIONS (4),
   # TEMP_REF (723.0 K, mean of the five temperatures), OUTPUT_NAMES
   # (('A', 'B', 'C', 'D')), OPTIM_OPTIONS ({'eps_1': 1e-11, 'eps_2': 1e-11},
   # LM step and gradient tolerances [-], notebook cell 32), BUILD_EXPERIMENT
   # ('698K': notebook cell 30 builds the reactor with that phase, which
   # modify_phase overwrites for every experiment), MODEL (ModelRevision),
   # MODEL_SOLVER (CVode settings) and REPLAY_RTOL (4 * machine epsilon).
   # Test helpers: stage1_seeds() fits ln k_i per temperature and returns the
   # Arrhenius-regression A_i [1/s] and E_a,i [J/mol]; initial_conditions()
   # returns {'673K': {'temp': 673.0, 'mole_conc': [...]}, ...} [K], [mol/L];
   # make_experiments() returns one Experiment per temperature with C_B and
   # C_C [mol/L] on time [s]; build_reactor(kinetics, phase) returns a
   # SimulationExec with a BatchReactor 'R01'; provenance() returns the data
   # sources and transformations.

   # Stage-2 reformulated kinetics seeded by the stage-1 Arrhenius regression.
   factors, activation = stage1_seeds()  # [1/s], [J/mol]
   kinetics = RxnKinetics(PURE, rxn_list=REACTIONS, k_params=factors,
                          ea_params=activation, reformulate_kin=True,
                          temp_ref=TEMP_REF)
   modifiers = initial_conditions()
   simulation = build_reactor(kinetics, modifiers[BUILD_EXPERIMENT])
   experiments = make_experiments()
   simulation.SetParamEstimation(x_data=experiments,
                                 phase_modifiers=modifiers,
                                 output_names=OUTPUT_NAMES)
   simulation.EstimateParams(optim_options=dict(OPTIM_OPTIONS), verbose=False)
   sources, transformations = provenance()
   names = simulation.ParamInst.name_params_total
   record = CalibrationRecord.from_estimation(
       simulation.ParamInst, experiments, case='ziegler-batch-reactor',
       parameter_units={name: '-' for name in names}, model=MODEL,
       sources=sources, transformations=transformations,
       model_solver=dict(MODEL_SOLVER, assimulo=assimulo.__version__))
   record.save('ziegler.json')

   # Reload and rerun through SimulationExec with fresh kinetics whose
   # A [1/s] and E_a [J/mol] invert the reformulation at the recorded seeds;
   # SetParamEstimation sets the exact seed vector through param_seed.
   loaded = CalibrationRecord.load('ziegler.json')
   inputs = loaded.estimation_inputs()
   seeds = inputs['param_seed']  # [-], phi_1,1..4 then phi_2,1..4
   ea_over_r = np.exp(seeds[NUM_REACTIONS:])  # [K]
   fresh = RxnKinetics(
       PURE, rxn_list=REACTIONS,
       k_params=np.exp(seeds[:NUM_REACTIONS] + ea_over_r / TEMP_REF),
       ea_params=gas_ct * ea_over_r, reformulate_kin=True, temp_ref=TEMP_REF)
   replay = build_reactor(fresh, initial_conditions()[BUILD_EXPERIMENT])
   replay.SetParamEstimation(**inputs)
   replay.EstimateParams(verbose=False, **loaded.optimizer_inputs())
   loaded.check_rerun(replay.ParamInst, rtol=REPLAY_RTOL, atol=0.0)

   # Or directly with a reactor's model callback; paramest_wrapper resets
   # the reactor and sets the parameters it receives before every solve, so
   # the replay reactor can be reused.
   loaded.rerun(replay.R01.paramest_wrapper, rtol=REPLAY_RTOL, atol=0.0)

Legacy compatibility adapters
-----------------------------

Model results are usually held as legacy state arrays (rows are samples,
columns are states) or ``{name: array}`` dictionaries. Four functions
convert them to and from ``FieldRecord`` objects without changing values,
ordering or NaN positions:

* ``fields_from_array(x, array, identities, x_units='s', experiment=None)``
  splits an array of shape ``(n, k)`` into ``k`` records, one per
  ``FieldIdentity`` in column order.
* ``fields_to_array(fields, names=None, experiment=..., kind=None)`` is its
  inverse: it returns ``(x, array)`` with the selected one-dimensional
  fields as columns in ``names`` order. The fields must share
  ``experiment``, ``x`` and ``x_units``; ``experiment`` and ``kind`` filter
  them, for example the ``'measurement_prediction'`` fields of one
  experiment of a captured record.
* ``fields_from_mapping(x, mapping, identities, ...)`` and
  ``fields_to_mapping(fields, experiment=..., kind=None)`` do the same for
  ``{name: array}`` dictionaries, whose entries may also be
  two-dimensional, ``(n, m)``, with component labels given through
  ``columns``.

Each column or entry is in the units of its identity; nothing is converted.

Adopted calibration cases
-------------------------

Two cases exercise the records end to end:

* **Analytic decay** (core test lane): the synthetic two-experiment decay of
  :doc:`experiment_measurement`, used above. ``tests/test_records_calibration.py``
  checks exact round trips, capture and rerun against closed-form values,
  and ``tests/test_records_simexec_capture.py`` checks the
  ``SimulationExec`` capture and both rerun paths with a closed-form unit.
  Its data are a verification fixture with origin ``'synthetic'``, not
  evidence of an empirical calibration.
* **Ziegler batch reactor** (Assimulo test lane): the workshop's
  multi-temperature Ziegler fit (data of unrecorded origin; issue #478),
  ``tests/test_records_ziegler_case.py``. The five experiments are fitted as
  ``Experiment`` objects through ``SimulationExec`` with reformulated
  Arrhenius parameters ``phi_1 = ln(k(T_ref) / (1/s))`` and
  ``phi_2 = ln((E_a/R) / K)`` [-] at ``T_ref = 723 K``, captured, saved,
  reloaded with unchanged observations, fitted values and covariance,
  rerun through both paths and compared with the 2023 workshop table. The
  original source of these data, and whether any license covers them, are
  not recorded upstream (issue
  `#478 <https://github.com/PharmaPy-org/PharmaPy/issues/478>`__). Its
  sources, the five CSV files, the initial concentrations and the
  pure-component database, therefore use origin ``'unknown'`` with only
  verifiable facts in ``sharing`` and ``description``, and SHA-256 digests
  of the files read. Its model revision is left empty because the model
  code is the PharmaPy checkout under test; users supply their commit.

The crystallization and bioreactor calibration cases planned for records
(issues `#358 <https://github.com/PharmaPy-org/PharmaPy/issues/358>`__ and
`#361 <https://github.com/PharmaPy-org/PharmaPy/issues/361>`__) are not yet
on the main branch; they will be adopted when those issues are resolved.
