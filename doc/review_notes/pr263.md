## Zero-radius FVM policy: future maintainer decision

**Disposition:** retaining `rad_zero=0` with a positive-start size grid is a
compatibility/modeling policy choice, not an unresolved defect identified by
this review. This PR preserves that convention. Its possible replacement is
future work, not a prerequisite to accepting the implemented fixes.

`rad_zero` and the size grid use micrometres. Nonzero nuclei must match the first
grid point within the documented floating-point allowance. Zero-radius nuclei
retain the legacy approximation at the first FVM cell even when the grid starts
above zero. A universal equality requirement would reject existing callers.
The restriction on analytical moment sensitivities is a separate contract;
accepting a legacy FVM grid does not establish analytical-sensitivity support.

The current contracts are documented in
[advanced usage](../online_docs/advanced_usage.rst) and exercised by
[`test_crystallizer_review_contracts.py`](../../tests/test_crystallizer_review_contracts.py),
particularly `test_finite_nuclei_require_matching_fvm_grid_edge`,
`test_fvm_supported_nucleus_grid_modes`, and
`test_analytical_sensitivity_support_is_checked_before_solver`.

Future work:

- [ ] Decide whether to retain the compatibility convention, require a
  zero-start grid, or define an explicit finite-cell nucleation treatment.
- [ ] Before tightening validation, inventory package, example, notebook, and
  test callers; document migration and any deprecation period.
- [ ] Compare population moments and nucleation mass across grid refinements
  using one explicit nucleus-size/boundary-flux convention. Agree numerical
  acceptance criteria before changing the default.

## Independent verification of the author's six reports

Sources are the author's
[four new-behavior findings](https://github.com/PharmaPy-org/PharmaPy/pull/263#issuecomment-5612125775)
and [two Filter regressions](https://github.com/PharmaPy-org/PharmaPy/pull/263#issuecomment-5623474496).
Verification used real phase/stream collaborators and native Assimulo where
integration was required: Python 3.11, NumPy 1.26.4, SciPy 1.17.1, and the
repository's locked Assimulo environment. The imported package path was checked
against the reviewed checkout.

Each reported behavior was checked independently of the earlier summary. The
relevant tests passed before deliberate source mutations. Reintroducing each
fault then made its targeted test fail for the intended reason. These failures
are evidence that the checks detect the defects, not failures of the restored
implementation. Source bytes were restored after every mutation; no mutation
was committed.

| Report | Verified result at the recorded revision | Test and deliberate reintroduction |
| --- | --- | --- |
